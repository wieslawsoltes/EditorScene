# Toolbar overflow input and lifetime

The seven native toolbar groups and their bound command items are retained. Escape closes a child submenu first and the root on the next key. The root presenter observes preview input on this application's Uno Skia desktop/browser hosts, before a native bubbling handler can consume it. A child-origin event never dismisses its root after restoring focus during that same event.

The all-group browser regression at candidate 4bd0384 (workflow 38555613992) then exposed a separate lifetime defect: after the File group had been dismissed, opening Edit could leave File, Edit and the root visible together. The assertion required exactly two popups and was not relaxed. The failed job retained its native state, console and trace.

Native source review found that CascadingMenuHelper starts a delayed-open timer on hover, but closing a submenu and unloading its owner do not stop that timer. Its tick opens a submenu without checking whether the owner remains loaded. The app now owns just the cancellable 400 ms hover schedule. It still uses the native MenuFlyoutSubItem and public IExpandCollapseProvider to expand/collapse the actual framework popup and preserve focus/command semantics. No private reflection, synthetic keyboard input, test-only mutation, popup-count override or direct Popup.IsOpen write is involved.

Exit, explicit activation, keyboard navigation, root closing and unloading cancel pending app hover work. A restarted timer's old queued tick cannot open the new hover before its deadline. Before a group opens, expanded peer owners are collapsed through their native pattern; this does not depend on the presenter's possibly stale single-child reference. Root closing also reconciles every expanded owner. Touch/pen/click and keyboard activation keep their native handler paths; hover is not disabled.

Primary implementation references inspected: Uno commit 345bb9cc352f8a7e932bf0e0f023f214aa11c895, `src/Uno.UI/UI/Xaml/Controls/MenuFlyout/CascadingMenuHelper.mux.cs`, `MenuFlyoutSubItem/MenuFlyoutSubItem.partial.mux.cs`, and `src/Uno.UI/UI/Xaml/Automation/Peers/MenuFlyoutSubItemAutomationPeer.cs` in https://github.com/unoplatform/uno . The native public pattern routes to the framework's normal Open/Close methods. This is an application-scoped repair, not a claim that every Uno version/platform has identical internals.

Validation retains the original Save All and command-binding tests, all seven clicked child/root pairs and root-only dismissal in both palettes. Added actual mouse hover tests open File, switch to Edit, open Search and verify no orphan popup reappears over repeated native observations beyond two hover periods after dismissal. Text, revision, modified state, tabs, document count and undo/redo advice remain unchanged. These definitions are not a passing result: the final candidate must still pass all three complete fresh browser runs, native checks, regressions and isolated package consumers before merge.
