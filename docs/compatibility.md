# Compatibility target and remaining work

EditorScene is an independent Uno implementation targeting documented Actipro SyntaxEditor capabilities. **It is not feature-complete, API/binary-compatible with the WPF product, or pixel-identical.** This document distinguishes implemented functionality from open parity boundaries. A CI pass covers its assertions, not every item in the target product.

| Area | Implemented scope | Remaining parity / validation |
| --- | --- | --- |
| Text engine | Persistent rope, UTF-16 offsets, immutable snapshots, owner-thread mutation, disjoint revision-checked edit sets, undo/redo, line indexing, snapshot-based save and revision-guarded load. | Exhaustive behavior comparison with Actipro, document property/service API compatibility, extreme-size memory/latency and file-provider failures on every platform. |
| Snapshot tracking and readers | Persistent bounded-chunk AVL line index and immutable line descriptors; cached unchanged snapshots; versioned points/spans, four boundary-affinity modes, reverse translation, undo/redo; bounded seekable TextReader with forward/backward code-unit/scalar reads, CR/LF/CRLF, checkpoints and clones; 4,096-character cached rope window. | Full vendor snapshot/token-reader/search/tagger contracts and migration adapters. Initial line indexing still scans the document, but position/line queries no longer materialize its full text. |
| Snapshot search | Reusable pooled literal search, bounded scopes, ordinal case modes, Unicode word edges, overlapping/non-overlapping enumeration, forward/reverse/wrapped lookup, cancellation and bounded literal replacement plans. | Complete vendor search providers and culture-sensitive/regex replacement contracts. Reverse literal lookup scans its region; native regex search remains a separate implementation. |
| Editing | Native keyboard/pointer editing, search/replace, regex via native search, indentation, case changes, line transforms, overstrike, primary-aware multiple selections, Select All Occurrences, matching-bracket navigation/selection, read-only preflight and grapheme/CRLF-safe multi-caret deletion. | Complete rectangular/virtual-space/drag/drop and all command edge cases; granular command enablement and full original keymap equivalence. ## Evidence rules

Unit results are in `artifacts/tests`; native results in `artifacts/native-checks.json`; package consumer results in `artifacts/packages/validation.json`. Browser results/screenshots/traces are in `artifacts/browser-tests` and the three `artifacts/browser-pass-*` folders. The browser LSP fixture retains its wire transcript in `lsp-protocol.json`. Read the result file and revision, not just the existence of an artifact: failed jobs also upload diagnostic artifacts.

Raw performance samples are in `artifacts/tests/performance.json`. The measurements report managed allocations and CPU microbenchmarks for named scenarios, not overall frame rate, latency or physical-GPU speed. Setup exclusions, baseline revisions, linear-time paths and warm-index costs are documented in [the editor review](editor-review.md), [structural selection and compiler analysis](structural-selection.md), [classic workspace](classic-workspace.md) and [diagnostic grid](diagnostic-grid.md). The sorted-query comparison measures cached versus uncached use of the same new implementation, not a comparison against Actipro. Unfavorable compiler results remain retained, and rounded zero-duration cached calls mean below timing resolution, not literally free execution.

The current native execution runner is Linux/X11. Browser automation uses Chromium with SwiftShader WebGL2, not a physical GPU. Other desktop and browser/device combinations remain unverified unless a separate result explicitly says otherwise. Browser automation has no source mutation API; it changes the app through actual user input and file pickers. Language-server integration tests connect through the real WebSocket transport to an explicitly identified synthetic protocol peer; they are not a claim of compatibility with every production language server. Workspace tests verify actual rendered diagnostic cells/icons, pointer/keyboard split and column input, sorting/navigation and status controls, not only view-model counts. Pages deployment runs only on main after all validation jobs succeed; branch validation is not itself a Pages publication.

See [diagnostic grid](diagnostic-grid.md), [classic workspace](classic-workspace.md), [structural selection and compiler analysis](structural-selection.md), [editor review](editor-review.md), [LSP integration](lsp.md), [macro details](macros.md), [snapshot reader details](snapshot-reader.md) and [architecture](architecture.md) for ownership and limitations. Reviews identify inspected changed paths and regression coverage; they are not exhaustive audits of every unmodified subsystem or device.
