# Compatibility target and remaining work

EditorScene is an independent Uno implementation targeting documented Actipro SyntaxEditor capabilities. **It is not feature-complete, API/binary-compatible with the WPF product, or pixel-identical.** This document distinguishes implemented functionality from open parity boundaries. A CI pass covers its assertions, not every item in the target product.

## Evidence rules

Unit results are in `artifacts/tests`; native results in `artifacts/native-checks.json`; package consumer results in `artifacts/packages/validation.json`. Browser results/screenshots/traces are in `artifacts/browser-tests` and the three `artifacts/browser-pass-*` folders. The browser LSP fixture retains its wire transcript in `lsp-protocol.json`. Read the result file and revision, not just the existence of an artifact: failed jobs also upload diagnostic artifacts.

Raw performance samples are in `artifacts/tests/performance.json`. They report managed allocations and CPU microbenchmarks for named scenarios, not frame rate, latency or physical-GPU speed. Setup exclusions, baseline revisions, linear-time paths and warm-index costs are documented in [editor review](editor-review.md), [compiler analysis](structural-selection.md), [classic workspace](classic-workspace.md), [diagnostic grid](diagnostic-grid.md), [diagnostic traversal](diagnostic-navigation.md), [editor options](editor-options.md) and [soft-tab input/scanning](soft-tab-backspace.md). Cached-query comparisons use the same new implementation, not Actipro. Cursor and soft-stop query probes are new workloads; the separate constructor comparison reproduces the previous scalar scanner against the new span scanner. Unfavorable dense-tab and compiler results remain retained; rounded zero-duration calls mean below timing resolution, not literally free execution.

Native execution currently uses Linux/X11. Browser automation uses Chromium with SwiftShader WebGL2, not a physical GPU. Other desktop and browser/device combinations remain unverified unless a separate result explicitly says otherwise. Automation has no source mutation API; it uses actual user input and file pickers. Language-server tests connect through real WebSocket transport to an identified synthetic protocol peer, not every production server. Workspace tests inspect actual rendered cells/icons, pointer/keyboard split and column input, sorting/navigation, native options and status controls. Pages deploys only main after all validation jobs succeed; branch validation is not itself publication.

See the linked feature documents, [LSP integration](lsp.md), [macro details](macros.md), [snapshot reader](snapshot-reader.md) and [architecture](architecture.md) for ownership and limits. Reviews identify changed paths and regression coverage, not exhaustive audits of every unmodified subsystem or device.
